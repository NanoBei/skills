持续追问用户，直到双方达成共识。目的是把想到的和没想到的问题都逼出来。把讨论组织成一棵**决策树**：每个决策都会分出依赖它的下级决策。发现风险、遗漏或矛盾时主动指出，不只被动提问。

开始前先读项目现有文档（如 `docs/PRODUCT.md`、`docs/ARCHITECTURE.md`），已确定的不再问；新结论与文档冲突时明确指出。

按**轮次**推进。**前沿**指前置条件都已确定的所有决策，也就是现在就能问、不必猜测尚未得到的答案的问题。每轮最多问约 5 个前沿问题，先问影响最大的，再逐步深入细节：逐题编号，并给出你的推荐答案。然后等用户回答，再进入下一轮。

用户每答完一轮，决策树都会随之变化：已确定的决策让前沿向外推进，依赖它们的问题随之解锁。重新计算前沿，再问下一轮。如果一个问题的答案取决于本轮另一个尚未回答的问题，它属于**后续**轮次，不放在本轮。

查明**事实**是你的事，不是用户的事。前沿问题需要环境中的事实（文件系统、工具等）时，派子代理去查；能自己查到的，不要问用户。不要因此卡住：正在进行的探查算作未确定的前置条件，只有依赖它的问题需要等子代理回报，其余前沿问题现在就问。**决策**归用户：逐个交给用户并等待答复。

前沿清空即讨论结束：决策树的每个分支都已走到，没有任何默认的假设。用户可随时喊停。在用户确认双方已达成共识之前，不要据此采取行动。

## 每轮格式

```
❓ **Q1** - **<问题标题>**：<问题正文，可分多段，可含多个选项>

➡️ <你的推荐答案>

---

❓ **Q2** - **<问题标题>**：<问题正文，可分多段，可含多个选项>

➡️ <你的推荐答案>
```

## 网页作答（可选）

用户说「用网页答」时，此后每轮：终端照常输出问题；同时把 [answer.html](./answer.html) 复制为系统临时目录下的 `grill-answer.html`（每轮覆盖），只替换其中 `<script id="data">` 的 JSON（格式见文件内注释），再用系统命令打开（macOS `open`、Linux `xdg-open`、Windows `start`）；打不开就给出文件路径让用户自己打开。用户在网页作答后会把汇总粘贴回来，按正常流程继续。

## 沉淀结论

用户确认达成共识后：

1. 列出结论，每条标明拟写入位置：需求 → `docs/PRODUCT.md`；技术/架构 → `docs/ARCHITECTURE.md`；需验证的技术方案 → `PROGRESS.md` 验证任务；其他问用户
2. 用户确认后再写入；目标文档不存在时，问用户写到哪
