# AGENTS.md

## 开工流程

每次会话前阅读：
1. `docs/PRODUCT.md` : 产品需求PRD
2. `docs/ARCHITECTURE.md` : 仓库整体结构和预期边界
3. `PROGRESS.md` : 项目任务状态

## 文档索引
- `README.md`：项目简介、安装和运行方式；需要运行项目或修改使用方式时读

## 工作规则
- 先想后写：需求不清先提问，不自行假设；有更简单的做法主动提出
- 保持简单、改动精准：只做需求内的事，不擅自加功能、不过度抽象、不顺手重构
- 需求或架构、接口有变更时，同步更新 `docs/PRODUCT.md` / `docs/ARCHITECTURE.md`
- 写文档遵守开头的「文档要点」注释，且不得删除该注释；新增文档须登记到 AGENTS.md「文档索引」
- 不得删除或弱化 `PROGRESS.md` 中已写明的验收标准；有误时在任务下标「待用户确认」并停下
- 任务完成后先 git 提交再开始下一项，提交信息用任务标题；非 git 仓库则跳过，不得自行初始化

## 回复要求
- 回复较长（多段落、多方案或多项改动）时，末尾加「快速总结」，通俗概括做了什么、当前决策是什么
